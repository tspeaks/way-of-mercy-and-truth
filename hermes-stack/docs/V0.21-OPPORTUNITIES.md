# What v0.20–v0.21 actually changes for this setup

Researched 2026-09-01 against the Hermes Agent release notes for
[v0.20.0 "Herald"](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.8.3)
and [v0.21.0 "Pantheon"](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.8.31)
(the patch tags v0.20.1–v0.20.6 in between shipped without granular notes —
their contents are rolled into the v0.21.0 summary). This is not about the
two open bugs in [`KNOWN-ISSUES.md`](KNOWN-ISSUES.md) — it's what to
actually *use* once this stack is upgraded and working, sorted by whether
it addresses something already in play here (needed) or is a genuine
improvement worth adopting on its own merits (desirable).

## Needed — ties directly into how this setup is already used

### `/topic` for real task parallelism

Telegram DMs now support user-managed multi-session topic mode —
`/topic <id>` restores a past session inline instead of everything living
in one linear thread. Already confirmed live on this bot (it showed up in
tonight's `/new` banner).

With the 20-task backlog split across `consulting-site` and
`lead-marshall`, this is the difference between working one task at a time
in a single thread and running both projects as separate topics
concurrently. Concretely: open one topic per project (or per in-flight
task, for the six COMPLEX bug-hunt tasks specifically, since those run
longest), and use `/topic <id>` to jump back into whichever one needs
attention instead of scrolling one shared history.

### Subagent steering, for firing off the backlog without babysitting

v0.21.0 added live steering of delegated/subagent tasks: course-correct
mid-flight, stop early, JSON-schema-validated output, per-delegation cost
tracking. `hermes/config.yaml`'s `delegation:` block already routes
subagents to `nvidia-kimi` — this feature makes it actually viable to hand
off several backlog tasks as subagents at once and step in on the ones
going sideways, rather than the tonight's task-4 pattern of discovering a
problem only after asking for a full status report.

Practical use: once the tool-calling bug is confirmed fixed, delegate the
independent COMPLEX bug-hunt tasks (1, 5, 8, 9, 12, 19) as subagents in
parallel instead of serially — they don't depend on each other, and this
is exactly the shape of work steering was built for.

### Tool self-recovery + iteration limit 90 → 500

`write_file` now verifies its own content, `patch` no-ops cleanly on
already-applied edits instead of erroring, oversized tool output spills to
a file instead of getting truncated mid-context. Combined with the 5.5x
iteration ceiling increase, longer tasks are far less likely to silently
stall partway through or lose their own edits to a truncated tool result.

This matters directly for the backlog's longer COMPLEX tasks (bug hunts
that touch the whole test suite, the security audit, the silent-failure
audit) — those are exactly the shape of task that used to risk running out
of iterations or losing tool output mid-run.

## Desirable — worth adopting for this repo's own maintenance burden

### `model_overrides` to absorb model-drift maintenance

New in v0.21.0: patch a model's context window or pricing without waiting
on a Hermes release. A large fraction of `preflight.sh`'s existing
comments exist purely because provider model ids and context windows drift
out from under `litellm/config.yaml` between checks (Groq retiring
`llama-3.3-70b-versatile`, Gemini's stale `/v1beta/models` listing, NVIDIA
NIM models 404ing despite appearing in the catalog). `model_overrides`
won't fix a genuinely deprecated model id, but for a context-window or
pricing drift it's a same-day fix instead of a `preflight.sh` catch +
config PR cycle.

Action: once upgraded, check whether `model_overrides` can express the
same corrections `preflight.sh` currently exists to catch, and whether
that changes what `preflight.sh` needs to check going forward.

### Per-model compression thresholds instead of one global percentage

`hermes/config.yaml` currently sets one `compression.threshold: 0.50`
across every tier. v0.20.0 added per-model threshold overrides and an
absolute `compression.threshold_tokens`. That matters here specifically
because the tiers span wildly different windows — local-coder's 28K vs.
`nvidia-kimi`'s 1M — so the same 50% trigger point means a genuinely
different amount of headroom on each. Worth revisiting once the current
compaction-leak bug (see `KNOWN-ISSUES.md`) is resolved, so a config change
here doesn't get confused with a bug retest.

### Check the new providers against the free-tier fallback chain

v0.21.0 added six new providers (Meta Model API, CommandCode, Tencent
TokenPlan, Nebius Token Factory, Ramp Router, Actual Computer). This
repo's whole `fallbacks:` chain in `litellm/config.yaml` exists to
maximize free-tier headroom before hitting a metered or rotating option —
worth a `preflight.sh`-style reachability check on whichever of these
publish a genuinely free tier, the same way this repo already vetted and
rejected SambaNova and DashScope/Qwen.

## Worth knowing about — lower priority, evaluate later

- **Cron job memory/continuity** — scheduled jobs now retain state between
  runs instead of starting cold. Relevant if Fun Task 3 (usage tracker) or
  Fun Task 4 (uptime monitor) from today's backlog get built as a cron job
  rather than a standalone script — the job could remember yesterday's
  baseline instead of recomputing it.
- **MCP command center (desktop app)** — a built-in dashboard with health
  checks and cost/usage tracking. Worth checking what it actually shows
  before building Fun Task 8 (a from-scratch personal dashboard) — may
  already cover most of what that task asked for.
- **Bot Mode / `hermes peer`** — named agents with their own continuity
  and group-chat-style bot-to-bot messaging. Could eventually split one
  Celesbot into project-scoped agents (one for `consulting-site`, one for
  `lead-marshall`) instead of a single bot juggling both, but this is more
  restructuring than the current setup needs — revisit only once the
  two-project backlog is under control, not before.
