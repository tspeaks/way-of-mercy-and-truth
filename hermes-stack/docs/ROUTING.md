# The routing table, and why each provider sits where it does

Verified against litellm 1.99.0 and a live proxy boot on 2026-09-01.

## Tiers

| Tier | Model | Provider | Why here |
|---|---|---|---|
| SIMPLE | `local-coder` | Ollama, RTX 2070 | Free and unmetered. Most requests, least thinking. |
| MEDIUM | `codestral` | Mistral | ~1B tokens/month is the largest free coding allowance in the stack. |
| COMPLEX | `nvidia-kimi` | NVIDIA NIM (Kimi K3, Moonshot AI) | 1M context, built for agentic coding tasks. |
| REASONING | `gemini-flash` | Google | Low-volume tier; the only remaining provider with real reasoning depth and headroom. Free-tier prompts may train Google's models. |

Measured with `scripts/explain-routing.py` against the live config:

```
rename the variable foo to bar                      SIMPLE     kw:rename    local-coder
fix the TypeError in the login handler, stack ...   COMPLEX    kw:fix       nvidia-kimi
write a function that parses ISO 8601 timestamps    SIMPLE     score        local-coder
refactor the auth module to use dependency inj...   REASONING  kw:refactor  gemini-flash
design a schema for multi-tenant billing with ...   MEDIUM     score        codestral
```

## Not in any tier

**`groq-fast`** — 30 RPM and 14,400 requests/day is generous, but 6,000 TPM is
not: that is one 6K-token request per minute. Rather than let the classifier
send it work it cannot hold, `max_input_tokens: 5000` fences it off. Pre-call
checks then skip it automatically for anything longer, and it serves as the
first fallback under `local-coder` — short prompts, which is what it is good at.
Note the limits are per *organisation*, not per key; more keys do not help.

**`offtopic` (Aion Labs)** — 20K tokens per *day*. That is a rounding error
against coding, and exactly right for Hermes' side-task slots: title generation,
MCP summaries, skills-hub lookups, TTS tags. It is wired into `auxiliary:` in
`hermes/config.yaml` and appears in no tier.

**`gemini-flash`** — the REASONING tier target and the long-context rescue.
Every `context_window_fallbacks` chain ends here because at 1M it is the only
deployment that can hold a prompt nothing else will take. Free-tier prompts
may be used to improve Google's products; that applies to REASONING-tier
prompts too, which may carry more design detail than a throwaway SIMPLE
request. Route anything sensitive through `local-tier.sh on` instead.

**`openrouter-free`** — the final fallback, after everything first-party has
failed or cooled down. Regenerated by `scripts/refresh-openrouter-free.py`.

**`cerebras-fast`, `cloudflare-llama`** — kept as fallbacks. Cerebras is fast
but capped at 8K; Cloudflare's daily neuron budget is small enough that it
earns `rpm: 3`.

**Qwen / DashScope is not in this stack.** No free tier exists for
`qwen3-coder-plus` or `qwen3-coder-flash` — confirmed directly in the Model
Studio console. `nvidia-kimi` (Kimi K3, 1M context) takes the COMPLEX slot
and the auxiliary roles (compression, triage, delegation) that Qwen would
otherwise have filled. The commented-out block stays in `config.yaml` and
`.env.example` in case Alibaba adds a genuinely free tier later.

**SambaNova is not in this stack.** Confirmed live 2026-09-01: the account
rejects requests with "A payment method is required." `gemini-flash` takes
the REASONING slot instead. The commented-out block stays in `config.yaml`
and `.env.example` in case that changes.

## Why "off-topic" is not a fifth tier

The obvious design is a TRIVIAL tier below SIMPLE. LiteLLM does support custom
tiers via `tier_definitions`, but it costs two things, both verified against the
source:

```
tier_definitions requires classifier_type 'llm' or 'custom':
the heuristic scorer only produces the built-in tiers
```

So every request would need an extra LLM call just to classify it — spending
free-tier quota to decide which free tier to spend. And with that fixed:

```
session_affinity cannot be combined with tier_definitions:
these features rely on the built-in tier severity order,
which a custom tier set does not define
```

Losing session affinity means a conversation can hop providers between turns,
discarding prompt cache and changing capability mid-thread. Two real costs to
route a category that Hermes already separates for us through `auxiliary:`.
The auxiliary slots were the better seam.

## Fallback order

Two independent chains:

- **`fallbacks`** fires on 429/5xx. Order is roughly local → generous
  first-party → metered first-party → aggregator.
- **`context_window_fallbacks`** fires when a prompt is too long for the chosen
  deployment. This is what saves the 5K Groq fence, the 8K Cerebras cap, and the
  28K local window from becoming hard errors.

`num_retries: 1` and `cooldown_time: 300` mean one retry, then a five-minute
bench for that deployment. That is deliberate: it stays inside each provider's
published limits rather than hammering the next one the moment the first says no.

## Keeping model ids honest

Free-tier model ids get retired with little notice — Groq deprecated
`qwen/qwen3-32b`, Cerebras dropped `qwen3-235b` from its free tier. `preflight.sh`
therefore fetches each provider's live `/models` list and checks every id the
config names, instead of trusting a comment written months ago.

## Privacy, per provider

| Provider | Prompts used for training? |
|---|---|
| Mistral free | **Yes, by default.** Opt out at Admin → Privacy before the first request. |
| Google Gemini free | Yes — free-tier data may be used to improve products. Paid tier does not. |
| OpenRouter | Varies per provider. Account-level privacy settings govern which are eligible. |
| Aion Labs, Groq, Cerebras, NVIDIA, Cloudflare | No published training use of API inputs on these tiers. |
| local-coder | Nothing leaves the machine. |

If a repo is under NDA, route it at the local tier or not at all. The stack
cannot enforce that for you — `scripts/local-tier.sh on` is the closest thing to
a switch for it.

## What would actually get you banned

Not this. Routing across providers you each have an account with, staying under
published limits, one key each, is ordinary API use. The things that cause
trouble are specific and avoidable, and none of them are in this config:

- multiple accounts or rotating keys to multiply a free tier
- sharing or reselling access
- routing through a relay that is itself violating an upstream vendor's terms
  (this is why Pollinations is commented out)
- sustained traffic above published limits

The `rpm`/`tpm` values throughout the config exist to keep the last one true.
